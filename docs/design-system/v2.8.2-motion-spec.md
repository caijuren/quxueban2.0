# 趣学伴 Design System v2.8.2 — 全局动效系统

> 版本：v2.8.2
> 目标：在 v2.8.0 Glass 与 v2.8.1 页面视觉升级基础上，建立克制、专业、全局统一的动效系统，让界面"有响应、有节奏、不拖沓"。

---

## 1. 背景

v2.8.1 已完成核心页面的 Liquid Glass 视觉升级：

- 首页 `/dashboard` 顶部 IdentityCard、快捷入口、数据摘要已 Glass 化
- 成长报告 `/dashboard/reports` 头部 Hero、学科分析、导出预览已 Glass 化
- AI 模块 `/dashboard/ai`、`/dashboard/ai-assistant` 诊断卡、对话气泡、输入区已 Glass 化
- 设置中心 `/dashboard/settings/*` 头部、导航、Section 已 Glass 化

当前界面视觉层次已有提升，但缺少统一动效：

- 页面加载时内容直接出现，缺少入场节奏
- 卡片/按钮悬停反馈不一致
- 主题切换偶有闪烁
- 数字变化、进度条更新缺少平滑过渡
- 未尊重系统"减少动态效果"设置

v2.8.2 将解决以上问题，建立一套全局 Motion System。

---

## 2. 设计原则

1. **克制优先**：动效服务于引导和反馈，不炫技。
2. **统一节奏**：同一层级动画使用相同时长和缓动，避免杂乱。
3. **性能优先**：仅使用 `transform` 和 `opacity`，避免布局抖动。
4. **尊重用户**：支持 `prefers-reduced-motion`，自动禁用非必要动画。
5. **渐进增强**：不破坏现有页面结构，以组件包裹方式引入。

## 3. Motion Token 规范

### 3.1 Duration Token

| Token | 值 | 使用场景 |
|---|---|---|
| `--duration-micro` | `100ms` | 按钮点击、图标切换、开关 |
| `--duration-hover` | `150ms` | 悬停、卡片展开、下拉菜单 |
| `--duration-layout` | `300ms` | 布局变化、路由切换、主题切换 |
| `--duration-entrance` | `400ms` | 页面加载、模态框出现、重要元素入场 |

### 3.2 Easing Token

| Token | 值 | 使用场景 |
|---|---|---|
| `--ease-out` | `cubic-bezier(0, 0, 0.2, 1)` | 关闭、收起、消失 |
| `--ease-layout` | `cubic-bezier(0.4, 0, 0.2, 1)` | 布局变化、主题切换、标准过渡 |
| `--ease-entrance` | `cubic-bezier(0.16, 1, 0.3, 1)` | 页面内容入场、模态框出现 |
| `--ease-spring` | `cubic-bezier(0.34, 1.56, 0.64, 1)` | 成功提示、轻弹效果 |

### 3.3 Stagger Token

| Token | 值 | 使用场景 |
|---|---|---|
| `--stagger-tight` | `40ms` | 密集列表项、菜单项 |
| `--stagger-default` | `50ms` | 普通卡片组、表单区（与迭代计划一致） |
| `--stagger-hero` | `80ms` | Hero 区域、核心数据卡 |

### 3.4 Transform Token

| Token | 值 | 使用场景 |
|---|---|---|
| `--hover-lift` | `translateY(-2px)` | 卡片悬停抬升 |
| `--hover-scale` | `scale(1.02)` | 可点击元素悬停放大 |
| `--press-scale` | `scale(0.98)` | 按钮/卡片点击按下 |
| `--entrance-offset` | `8px` | 入场动画初始位移 |

## 4. 动效组件

新增 `components/motion/` 目录，包含以下组件：

### 4.1 `FadeIn`

- 功能：透明度从 0 到 1 的淡入
- 默认时长：`--duration-entrance`
- 默认缓动：`--ease-entrance`
- 支持 `delay`、`duration`、`className` 扩展
- 支持 `once` 属性控制是否只触发一次

### 4.2 `SlideUp`

- 功能：从下方 `var(--entrance-offset)` 位移 + 淡入
- 默认时长：`--duration-entrance`
- 默认缓动：`--ease-entrance`
- 支持 `delay`、`distance`、`className`
- 用于页面主要内容入场

### 4.3 `StaggerContainer` / `StaggerItem`

- 功能：子元素按顺序错落入场
- 容器控制 `stagger`、`duration`、`delayChildren`
- 子元素继承动画配置，自动计算 `delay`
- 默认间隔：`--stagger-default`（50ms，与迭代计划一致）
- 用于卡片组、列表、导航项

### 4.4 `ScaleOnHover`

- 功能：悬停时轻微放大/抬升
- 默认：`translateY(-2px) scale(1.01)`
- 默认时长：`--duration-hover`
- 支持 `scale`、`lift`、`disabled` 属性
- 可与 `GlassCard` 组合使用

### 4.5 `CountUp`

- 功能：数字从初始值平滑增长到目标值
- 支持 `duration`、`decimals`、`suffix`、`prefix`
- 使用 `requestAnimationFrame` 实现，不依赖外部库
- 支持 `prefers-reduced-motion` 下直接显示最终值

### 4.6 `ProgressBar`

- 功能：进度条平滑过渡
- 支持 `value`、`max`、`animated`、`className`
- 进度变化时使用 `transform: scaleX()` + `transform-origin: left`
- 默认时长 `--duration-layout`，缓动 `--ease-entrance`
- 支持 `prefers-reduced-motion` 下无动画

### 4.7 `MotionProvider`

- 功能：全局监听 `prefers-reduced-motion`
- 提供 `useReducedMotion()` Hook
- 所有 motion 组件统一读取该上下文
- 服务端默认渲染为 `false`

## 5. 全局动效规则

### 5.1 页面首次加载

- 页面整体使用 `StaggerContainer`
- Hero 区域元素间隔 `80ms`
- 普通卡片组间隔 `60ms`
- 列表项间隔 `40ms`
- 所有子元素使用 `SlideUp` 或 `FadeIn`

### 5.2 卡片悬停

- `translateY(-2px)` + 阴影扩散
- 时长 `var(--duration-hover)`（150ms）
- 禁用态无悬停效果
- 已通过 `GlassCard hover` 实现的区域，保持并统一参数

### 5.3 按钮点击

- `scale(0.98)`，时长 `100ms`
- 主按钮、次按钮、幽灵按钮统一
- 加载态/禁用态无点击反馈

### 5.4 主题切换

- 所有颜色过渡 `300ms`
- 使用 `transition-colors duration-layout`
- 避免闪烁

### 5.5 模态框/Dialog

- 内容：`scale(0.96) opacity(0)` → `scale(1) opacity(1)`
- 时长 `200ms`
- 缓动 `ease-entrance`
- 遮罩：`opacity(0)` → `opacity(1)`，时长 `150ms`

### 5.6 路由切换

- 当前阶段以页面内元素入场为主
- 暂不做页面级路由切换动画（避免 Next.js App Router 复杂度）

## 6. 基础组件增强

### 6.1 `Button`

- 添加 `:active` 状态 `scale(0.98)`
- 过渡使用 `--duration-micro`
- 加载态 Spinner 使用 `animate-spin`
- 不影响现有 variant/size 体系

### 6.2 `GlassCard`

- 保留现有 `hover` 属性
- 内部统一使用 `--duration-hover` 和 `--ease-layout`
- 悬停位移统一为 `var(--hover-lift)`
- 新增 `motion` 属性控制是否启用入场动画（默认 `false`，在页面中手动包裹 `StaggerContainer`）

### 6.3 `Card` / `Section`

- 统一添加 `transition-colors duration-layout`
- 支持主题平滑切换

## 9. 技术实现要点

### 9.1 不引入新依赖

- 项目已有 `framer-motion`，但本阶段优先使用 CSS Transition + 简单 React Hook 实现
- 若 `framer-motion` 能显著简化 `StaggerContainer` 或 `CountUp`，可在组件内部选择性使用
- 禁止在业务页面直接写复杂 `framer-motion` 动画

### 9.2 prefers-reduced-motion

```css
@media (prefers-reduced-motion: reduce) {
  *,
  *::before,
  *::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
  }
}
```

同时 `MotionProvider` 检测该媒体查询，所有动效组件读取该状态并跳过动画。

### 9.3 性能要求

- 动画仅使用 `transform` 和 `opacity`
- 避免动画 `width`、`height`、`top`、`left`
- 谨慎使用 `will-change`，动画结束后移除
- 首屏加载动效不阻塞关键内容渲染

## 11. 风险与应对

| 风险 | 影响 | 应对策略 |
|---|---|---|
| 动效过多导致视觉疲劳 | 体验下降 | 严格遵循时长规范，优先做入场和悬停两类 |
| 低端设备掉帧 | 性能问题 | 使用 CSS transform，支持 reduced-motion 降级 |
| 与现有组件样式冲突 | 回归问题 | 所有改动通过 className 扩展，不覆盖原逻辑 |
| Next.js 服务端渲染动画闪烁 | 首屏异常 | MotionProvider 服务端默认 `reducedMotion=true`，CSR 后再检测 |
