# v2.7.4 硬编码清理规范

> 版本：v2.7.4 Cleanup  
> 目标：把项目中分散的硬编码颜色/样式全部收敛到 Token 或组件。  
> 状态：规范文档（待实现）

---

## 1. 目标与范围

### 1.1 目标

1. 清理 `app/` 和 `components/` 中所有硬编码颜色。
2. 统一不一致的间距、圆角、阴影、字号用法。
3. 用新原子组件替换页面中重复实现的 UI 元素。
4. 让 Design Token 成为唯一视觉来源。

### 1.2 范围

- `app/` 目录下的所有 TSX/TS 文件。
- `components/` 目录下的所有 TSX/TS 文件。
- 重点清理：Admin 页面、设置页面、控制台页面、表格、表单。

### 1.3 不在范围

- `miniapp/` 小程序端（保持独立）。
- `prisma/`、`scripts/`、`public/`。
- 复杂营销页特殊效果（保留但归档）。
- 复杂数据可视化配色（单独处理）。

---

## 2. 当前状况

根据 v2.7.0 统计：

- `app/` 目录：57 处硬编码色值
- `components/` 目录：149 处硬编码色值
- 总计：约 206 处

清理目标：减少 90% 以上，剩余部分必须有明确注释说明。

## 3. 清理策略

### 3.1 扫描方法

1. 使用 Grep 搜索硬编码颜色：
   ```bash
   grep -rE '#[0-9a-fA-F]{3,8}\b' app/ components/ --include='*.tsx' --include='*.ts'
   ```
2. 使用 ESLint 拦截新增硬编码颜色。
3. 使用 Prettier 统一 className 格式。

### 3.2 分类处理

| 类型 | 示例 | 处理方式 |
|---|---|---|
| 通用 UI 颜色 | `bg-[#111522]`, `text-white` | 替换为对应 Design Token |
| Tailwind 默认色板 | `bg-slate-800`, `text-gray-400` | 替换为 Design Token |
| 图表/可视化 | 折线图、饼图颜色 | 纳入数据可视化 Token 或加注释保留 |
| 营销页特效 | Hero 渐变、特殊背景 | 加 `/* marketing-only */` 注释保留 |
| 图标渐变 | `from-blue-500 to-cyan-500` | 替换为品牌/状态色 Token |

## 6. 特殊情况处理

### 6.1 营销页保留

营销页特殊效果允许保留硬编码，但必须加注释：

```tsx
{/* marketing-only: not part of design system */}
<div className="bg-gradient-to-r from-[#ff2d6a] to-[#8b5cf6]">
```

### 6.2 数据可视化保留

图表颜色允许保留，但需归档到 `docs/design-system/data-viz-tokens.md`（可在 v2.7.4 后补充）。

### 6.3 图片/渐变背景

使用图片或复杂渐变作为背景的，允许保留，但建议逐步替换为 Token。

---

## 7. 验收标准

- [ ] `app/` 和 `components/` 中硬编码颜色减少 90% 以上。
- [ ] 剩余硬编码颜色都有明确注释说明。
- [ ] ESLint `no-restricted-syntax` 规则通过。
- [ ] `pnpm prettier --check .` 通过。
- [ ] 视觉回归测试无意外差异。
- [ ] 深色和浅色主题下关键页面正常显示。

---

## 8. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 替换后视觉效果变化 | 中 | 按模块替换，每模块替换后立即本地验证。 |
| 误删业务逻辑 | 低 | 只改 className，不动 JSX 结构和事件处理。 |
| 某些颜色没有对应 Token | 中 | 新增 Token 到 v2.7.0 规范中，并更新文档。 |
| 清理工作量超预期 | 中 | 分批进行，允许部分 P2 组件延后处理。 |
